## 一、谁管什么

| 事 | 正本 | 界面做什么 |
|---|---|---|
| 新消息、正在输入**提不提示**、同一会话 7 秒内只响一声、重连补发汇总 | `atg-core::notify`（`Policy::observe` 出 `Judged`；人定见 `docs/plan/009_decisions-notify-v0.md`） | 把每批事件交给它，拿回判定 |
| 状态变化**播不播**：防抖 2 秒、成对、合并 | `specs/contracts/errors.md` 第一节第 4 小节（003 E1、003 E2） | 同上 |
| **说的那句话** | `atg-core::speech`（读 `Doc::Alert` / `Doc::Status` / ……） | 拿到字符串，不改 |
| **人停没停手**（「停手后再说」的那个时刻） | ⚠️ 现在没有正本：`notify` 只收 `set_user_idle(bool)`（`src/atg-core/src/notify.rs:329`），「选中项字数 × 180 ms + 1 秒」的估算（exp004 模式 5，001 拍板 3 ⑤）还没地方放 | 建议归 `notify`（纯函数、时钟可注入）；界面只报「按了键」「选中项是哪条」。已列进 012 第八节 |
| **走哪条路、什么优先级** | 本文第三节路由表 | 照表执行 |

界面里**不许出现**节流、防抖、合并的常数（012 第二节第 12 行，`check-gui-state.py` 扫）。

## 二、五条出路（`001` 第二节第 2 小节；exp001、exp004 实测）

| 出路 | 怎么做 | 特点 |
|---|---|---|
| **Live 节点** | 一个 `Status` 角色的不可见节点设 Live + 值；GPUI 经 `a11y_synthetic_children` 写（exp001） | 随下一帧进树，**agent 读树也看得到**；窗口被挡 / 后台时不出帧就滞后（exp004「风险」）；优先级只有 50 / 90 |
| **直发公告** | 主线程直接发 `NSAccessibilityAnnouncementRequestedNotification` | 不等帧；能发最低优先级 10（exp004 结论 1）；agent 读树看不到 |
| **提示音** | 只响一声，每次复制一份声音对象再播（exp004 结论 8） | 不占朗读通道 |
| **写进名称** | 窗口标题、列表名带上新消息数（001 拍板 3 ⑥） | 不主动说，人回去时自然听到；agent 读树看得到 |
| **系统通知**（第五条，后台专用） | macOS 通知中心，要通知权限（001 拍板 4） | VoiceOver 读横幅；点通知打开那条（M4.4） |

## 三、路由表

应用状态三种：**前台**（本应用窗口在最前）· **被挡**（本应用在前台但窗口被盖住、或窗口不是 key）· **后台**（人在别的应用里）。

每个来源一行、三种状态各一格；「—」= 这种状态下这个来源不会出现（如人按了键必在前台），单测把「—」当「不出声」核。

| 来源（`source`） | 前台 | 被挡 | 后台 | 档位 | 出处 |
|---|---|---|---|---|---|
| `new_message`（`notify` 判定提示，`sound:true`） | 提示音 + 写进名称；停手后说汇总（Live） | 提示音 + 写进名称；停手后说汇总（直发） | 系统通知 | 低 | 001 拍板 3、4 |
| `new_message_burst`（同一会话 7 秒内的后续，`sound:false`） | 只更新名称里的数 | 只更新名称里的数 | 系统通知（⏳ 合并成一条还是逐条，看系统通知的分组） | — | 009 第 2 条 |
| `reconnect_summary`（`Judged::Summary`） | 提示音 + 说汇总（Live） | 提示音 + 说汇总（直发） | 系统通知 | 低 | 009 第 10 条 |
| `peer_typing`（对方正在输入；当前打开的私聊、人停下时。和界面动作 `typing`——我方发「正在输入」——方向相反，别混） | 说一次（Live） | 不说 | 不说 | 低 | 003 F6、005 N5 |
| `status_bad`（`offline` `connecting` `syncing` `fault`） | Live | 直发 | 不说（⏳ 要不要系统通知） | `fault` / `offline` 高；其余低 | `errors.md` 第一节第 4 小节 |
| `status_ok`（`online`，只在播过坏状态后） | Live | 直发 | 不说 | 低 | 003 E2 |

**档位怎么落到值**（单测照此核）：

| 档位 | 直发公告的优先级 | Live 节点 |
|---|---|---|
| 最低 | 10 | 不用 Live（Live 没有这一档） |
| 低 | 10 | Polite（50）——Live 只有 50 / 90 两档 |
| 高 | 90 | Assertive（90） |

不用「中」：Live 上「中」和「低」都是 50，分不出来。

表注：

- **「低」在 Live 上只能是 Polite（50）**（上表）：accesskit_macos 只发 50 / 90（`event.rs:38-41`，exp004 结论 1）。前台要 10 就得改走直发，代价是 agent 读树看不到这句。前台默认 Live，是为了「AI 友好」那把尺子；⏳ 人试听若觉得 Polite 太抢，前台也改直发（001 R1：礼貌式会插进朗读）
- **常驻**：当前用户状态同时写进窗口标题和状态栏名称（`errors.md` 第一节第 4 小节）；新消息数同时写进窗口标题和两个列表名。这两项是「写进名称」，和上表的「说」并行
- ⏳ GPUI 上游若加了原生的 live / announce 接口（`findings-gpui.md`），Live 节点那条出路换实现，本表不变

## 四、去重与防重复

| 情形 | 做法 | 出处 |
|---|---|---|
| 同一句连着说两次 | Live 节点**换节点**（标识 `live:<序号>`，序号单调增），不用零宽字符 | exp001 结论 3 及「改变了哪一个取舍」 |
| **AccessKit 升级会改播报的触发字段**：accesskit_macos 0.26.3 是值变了才播，0.27.0 起改成名称变了才播（上游提交 `e6ae72f` #782） | Live 节点的**名称和值设成同一句**，两个版本都播；升级后改成只设名称，并重跑播报自测 | `findings-gpui.md` 第 3 节（读源码） |
| 改 Live 属性时值不空，会多说一次 | 播报器只在「值为空」时切 Live 级别 | exp001 结论 4 |
| 焦点刚移动就发公告，常被吞 | 播报器把公告**延后**（不丢）到焦点移动之后 `FOCUS_SETTLE_MS` 再发；高档也延后 | `findings-a11y.md` 第五节第 1 小节（社区）；清单 A6 |
| D 键展开时名称变、又直发详情，可能叠读 | 先改名称，再隔 `FOCUS_SETTLE_MS` 直发详情；⏳ 人听是否叠读，叠的话展开时名称改动推迟到详情说完 | B19-6 |
| 同类消息排队（连接状态连变几次） | 入口带**类别**：同类别只留最新一条（照 Windows UIA 通知的「只留最新」语义） | `findings-a11y.md` 第五节第 2 小节 |
| 流式变化（转写进行中、对方编辑中） | 中间态不播，稳定后整句播一次 | 同上第五节第 1 小节 |
| 同一条消息判两次 | 归 `notify`（新消息与「最后一条变了」只判一次，`notify.rs` 文件头） | — |
| 窗口被挡时 Live 滞后到下一次按键才发 | 被挡、后台不走 Live（上表） | exp004 结论 5 |
| 树导出看不到 Live | 导出器从播报器的记录补一行 `live=polite` | exp001 末段；`a11y-tree.md` 第四节 |

**出声时机常数**（界面里只有这两个，`check-gui-state.py` 白名单；012 第二节第 12 行）：

| 常数 | 值 | 用在 |
|---|---|---|
| `FOCUS_SETTLE_MS` | 500 ms | 焦点移动之后延后发公告（上表）|
| `SEARCH_COUNT_DEBOUNCE_MS` | 400 ms | 来源 `search_count`：搜索框停止输入后再播结果数（清单 A19）。搜索是界面自己的查询，不经 `notify`，所以防抖在这里；新消息、状态的节流仍全在 core |

## 五、详略设置

MVP 就做一项：「新消息播报：汇总 / 只计数 / 关」（人定 B19-8；`findings-a11y.md` 第五节第 2 小节）。设置值进 `notify::Config` 一处（core 要加这个字段，已列 012 第八节），界面只提供开关。「只计数」= 照常提示音 + 写进名称，停手后不说汇总；「关」= 只写进名称

## 六、正例与反例

| | 例 | 为什么 |
|---|---|---|
| ✅ | 人正在 ↓ 浏览，来了 2 条：只响一声，标题变「……，2 条新消息，按 M 收听」；人停手约 2 秒后说「2 条新消息，最新：……」 | 001 拍板 3 的组合（exp004 模式 3 + 6 + 5） |
| ❌ | 来一条就立刻用 Polite 说一句 | 会插进朗读（exp001 人工试听） |
| ❌ | 播报器里写 `if now - last < 7000 { return }` | 节流常数在界面里，和 `notify` 的 `burst_ms` 成了两份 |
| ❌ | 界面里 `format!("{} 条新消息", n)` | 句子不从 `speech` 出（守则 3） |
| ✅ | 人在别的应用里，来了一条私聊：系统通知；点它打开这个会话、选中那条 | 001 拍板 4；M4.4；`focus.md` `chat_opened_from_notification` |
| ❌ | 人在别的应用里，走 Live 节点 | 不出帧，等于没提醒（exp004「风险」） |
