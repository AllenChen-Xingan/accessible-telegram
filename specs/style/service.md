句子形状是「谁做了什么，钟点」，和普通消息不同，中间没有冒号：系统消息是一件事，不是谁说的一句话。这个形状沿用现代码与快照，人还没实听过。在会话项里当最后一条时不读钟点（`chat-item.md` 例 C14）。

## 一、成员进出

### 例 S1 加入了 Telegram

夹具：会话 101；actor user 101 林小雨；action contact_registered；时间 19:20。

正例：

林小雨加入了 Telegram，19:20

反例：

系统消息，林小雨加入了 Telegram，19:20

错在哪：「系统消息」几个字没有信息，只多读一秒。

### 例 S2 拉别人进群

夹具：actor user 102 周大山；action members_added，users 为 user 101 林小雨、user 103 陈一一；时间 18:40。

正例：

周大山添加了林小雨、陈一一，18:40

反例：

周大山添加了林小雨，周大山添加了陈一一，18:40

错在哪：一件事拆成两句，顿号连读就够。

### 例 S3 自己进群

夹具：actor user 103 陈一一；action members_added，users 只有 user 103 陈一一；时间 19:10。

正例：

陈一一加入了群组，19:10

反例：

陈一一添加了陈一一，19:10

错在哪：添加的就是自己，要说成「加入」。

### 例 S4 通过邀请链接、通过入群申请

夹具 A：actor user 103 陈一一；action joined_by_link；时间 19:32。

正例：

陈一一通过邀请链接加入了群组，19:32

夹具 B：actor user 103 陈一一；action joined_by_request；时间 19:33。

正例：

陈一一的入群申请已通过，19:33

### 例 S5 退出和被移出

夹具 A：actor user 103 陈一一；action member_removed，user 为 user 103 陈一一；时间 19:34。

正例：

陈一一退出了群组，19:34

反例：

陈一一移出了陈一一，19:34

错在哪：操作人和被移出的是同一个人，就是自己退出。

夹具 B：actor user 102 周大山；action member_removed，user 为 user 101 林小雨；时间 19:34。

正例：

周大山移出了林小雨，19:34

## 二、群资料变动

### 例 S6 改群名（V23）

夹具：actor user 102 周大山；action title_changed，title 周末爬山群十月版；时间 19:31。

正例（新名字加直角引号）：

周大山把群名改为「周末爬山群十月版」，19:31

反例：

周大山把群名改为周末爬山群十月版，19:31

错在哪：V23 人定加引号，好听出名字在哪结束。人实听后再定。

### 例 S7 在频道里改名、换头像

夹具：会话 -1002 示例频道，kind channel；actor chat -1002 示例频道；action title_changed，title 示例频道周刊；时间 08:00。

正例：

示例频道把频道名改为「示例频道周刊」，08:00

现状：

示例频道把群名改为「示例频道周刊」，08:00

错在哪：频道不是群，代码要改。换头像同理，频道里读「更换了频道头像」。单独读一条系统消息时，读法拿不到会话类型，见缺口第 2 条。

### 例 S8 换头像、删头像

夹具 A：actor user 102 周大山；action photo_changed；时间 19:34。

正例：

周大山更换了群头像，19:34

夹具 B：同上，action photo_deleted。

正例：

周大山删除了群头像，19:34

### 例 S9 建群

## 三、置顶（V16）

### 例 S10 置顶了一条消息

夹具：actor user 102 周大山；action pinned，pinned 指向会话 -1001 的消息 1001（周大山发的「集合点改到北门」）；时间 19:31。

正例：

周大山置顶了一条消息：集合点改到北门，19:31

现状：

周大山置顶了一条消息，19:31

实现提醒：要投影时查被置顶那条的内容。那条查不到、受限或已删时怎么读，人还没定；先照现状只读「置顶了一条消息」，已报大总管。内容不截断。

## 四、操作人或对象是自己（V17）

### 例 S11 自己做的

夹具：actor 是自己 user 100（名字「我自己」）；action title_changed，title 周末爬山群十月版；时间 19:31。

正例：

我把群名改为「周末爬山群十月版」，19:31

现状：

我自己把群名改为「周末爬山群十月版」，19:31

错在哪：自己一律读「我」（原则）。系统消息现在不知道操作人是不是自己，见缺口第 1 条。

### 例 S12 被操作的是自己

夹具 A：actor user 102 周大山；action members_added，users 只有自己 user 100；时间 18:40。

正例：

周大山添加了我，18:40

现状：

周大山添加了我自己，18:40

夹具 B：actor user 102 周大山；action member_removed，user 为自己 user 100；时间 18:50。

正例：

周大山移出了我，18:50

现状：

周大山移出了我自己，18:50

反例：

你被周大山移出了群组，18:50

错在哪：V17 人定用「我」，和别处一致。

## 五、名字查不到（V18）

V18 人定分场合：消息发送人叫「未知发送人」；系统消息的操作人叫「有人」；被添加、被移出的人叫「未知用户」。会话标题为空见 `chat-item.md` 例 C7、C8。

### 例 S13 操作人名字还没到

夹具：actor user 105，名字为空；action members_added，users 为 user 103 陈一一；时间 19:00。

正例：

有人添加了陈一一，19:00

现状：

未知发送人添加了陈一一，19:00

### 例 S14 被添加的人名字查不到、或已注销

夹具 A：actor user 102 周大山；action members_added，users 为 user 105，名字为空；时间 18:40。

正例：

周大山添加了未知用户，18:40

现状：

周大山添加了未知发送人，18:40

夹具 B：同上，但 users 为 user 107，名字为空，用户类型 deleted。

正例（V14 题面写明系统消息被操作的人跟它走，人定已注销都读「已注销的账号」）：

周大山添加了已注销的账号，18:40

现状：

周大山添加了未知发送人，18:40

实现提醒：被操作的用户要带用户类型，见缺口第 5 条。

## 人定结果（2026-10-26）

记录正本：`docs/plan/007_decisions-b15.md`。每题留着题面、选项、代价，以后要翻案时查。V1 到 V7、V20 在 `chat-item.md`，V8 到 V15、V21、V22 在 `message.md`。

### V16 置顶消息要不要带内容

题面：例 S10。

选项：A 只读「某某置顶了一条消息」。B 带上被置顶那条的内容，「某某置顶了一条消息：内容」。

代价：B 要投影时查被置顶那条；那条很长时整句也很长；那条受限或已删时要另给说法。A 要按详情或去置顶栏才知道置顶了什么。

人定 2026-10-26：B，带内容。

### V17 被操作的人是自己时怎么说

题面：例 S12。

选项：A「周大山添加了我」「周大山移出了我」。B「你被周大山添加进群」「你被周大山移出了群组」。

代价：A 和「我：……」一致；B 和本项目别处用「我」不一致。

人定 2026-10-26：A。

### V18 名字查不到时统一怎么叫

题面：例 S13、S14，以及 `message.md` 例 M27、`chat-item.md` 例 C15。

选项：A 人一律叫「未知发送人」。B 分场合：消息发送人叫「未知发送人」；系统消息的操作人叫「有人」；被添加、被移出的人叫「未知用户」。C 人一律叫「未知用户」。

代价：A 里「添加了未知发送人」说不通；B 每处都通顺，要记三种说法；B、C 都要改第九节「名字查不到一律读未知发送人」那句。

人定 2026-10-26：B，分场合（人单独选）。

### V19 没做读法的系统消息读什么

题面：例 S15。规约第九节写「一律读暂不支持的消息」，现代码读「一条系统消息」。

选项：A「一条系统消息」。B「暂不支持的消息」。C「暂不支持的系统消息」。

代价：A 和规约不一致；B 和普通消息分不开；C 多两个字。

人定 2026-10-26：C，「暂不支持的系统消息」。

### V23 系统消息里的新名字要不要加引号

题面：例 S6、S9。新群名加直角引号，为了让人听出名字在哪结束。VoiceOver 念不念、停不停，没实测。

选项：A 加直角引号。B 不加。C 不加引号，改成「把群名改为：新名字」。

代价：A 如果 VoiceOver 不停顿，引号白加；B 名字和钟点之间只靠逗号隔开；C 多一个冒号停顿。

人定 2026-10-26：A，加，待人实听后再定。

## 给大总管的缺口（数据或规约的问题，不是读法题）

1. 系统消息的操作人、被操作的用户，都不知道是不是自己，读不出「我」（S11、S12）。要么投影时给 Sender、UserRef 标出自己，要么读法上下文带本账号 id。动 `specs/content-tree.md` 第三节
2. 单独读一条系统消息时，读法只拿到 Service，拿不到所在会话是群还是频道（S7）。在会话项里读最后一条时，chat_brief 手上有会话类型，不受影响
3. 规约要同步：V18、V19 人定后，`specs/content-tree.md` 第九节「名字查不到一律读未知发送人」「没做读法的一律读暂不支持的消息」两句要改，系统消息有自己的说法。那份不归 style 改
4. 置顶带内容（S10、V16）要投影时取被置顶那条；那条查不到、受限或已删时怎么读，人没定
5. 被操作的用户要带用户类型，才能读「已注销的账号」（S14 夹具 B、V14），和 `message.md` 缺口第 1 条的 Sender 一起加
6. 人没定的：系统消息的操作人已注销时读什么（V14 管发送人和被操作的人，V18 的「有人」管名字没到），待人定
