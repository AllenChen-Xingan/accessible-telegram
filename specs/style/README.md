# specs/style — 风格档案

> 无障碍 Telegram（macOS · VoiceOver 优先） 的风格真相源。**风格不住在真相源里，住在规约里**——
> `vault/` 管「事实是什么」，这里管「产出该长什么样」。

## 为什么风格不放 vault

`vault/raw` 是别人的原件，`vault/truth` 是整理后可引用的事实。**风格不是事实，是标准。**
真相源解决「是什么」，解决不了「应该是什么」——所以它归规约。

## 一句话

> **形容词自述不可靠，可靠的是你亲手改掉的每一处。风格不是宣言，是改稿史的压缩。**

## 放什么

| 文件 | 装什么 |
|---|---|
| `positive.md` | **正例**：人亲手定标的那一份成品。它比任何形容词都准 |
| `negative.md` | **负例**：反向问一次「怎样最快毁掉它」，把答案收成清单 |
| `lexicon.md` | 用词表：禁用词、替换词、术语体例 |
| `samples/` | 定标样本原件（改前 → 改后成对保存） |

读法规约（读屏读出的那句话，v0，2026-10-26 人定，记录在 `docs/plan/007_decisions-b15.md`；原则正本 `specs/content-tree.md` 第九节）。**读法以这三份为准，快照跟着这三份改**：

| 文件 | 管什么 |
|---|---|
| `chat-item.md` | 会话列表一项怎么读，含人定 V1–V7、V20 |
| `message.md` | 一条消息怎么读，含人定 V8–V15、V21、V22 |
| `service.md` | 系统消息怎么读，含人定 V16–V19、V23 |

### 三份读法规约共用的约定

用 VoiceOver 读这几份时，建议打开 Markdown 的渲染视图，否则会念出井号和反引号。

每个例子最多有这几行，每句例句单独一行：

- 夹具：能直接写成测试输入的字段
- 正例：照人定和原则该读的那一句。读法以本文为准，快照跟本文；人以后要改说法，改本文，快照照它回填
- 现状：现代码读出的和正例不同时才有这一行，表示代码要改
- 反例：容易写错成的那句，后面跟「错在哪」，写明违反哪条原则或哪个 R 号
- 「现在快照填」：人定的读法要等数据（比如 #43），数据到之前快照暂填的那一句
- 「没有展开键时」：调用方不给展开键（比如命令行）时该读的样子。没写这一行的例子，照规则把「，按 D 展开」整段去掉
- 「错在哪」「说明」也可以跟在现状行后面，解释代码为什么要改

夹具的默认值，没写就按这个：

- 「私聊」包括 kind private 和 secret（私密聊天），现代码也一样对待
- 时区东八区，读法上下文 utc_offset 为 28800；时间写成钟点，测试里换算成 Unix 秒
- 人名「为空」指 name 为 None（现代码对空字符串也同样处理）；会话 title「为空」指空字符串
- 未读 0、提到你 0、未静音、未置顶；outgoing false；没有回复、转发、附件、隐藏内容；表情回应的 chosen 为 false
- 消息 id、系统消息 id 不影响读法，可以任取
- 读法上下文的 listen_key 为 None；outgoing 为 true 时，发送人是 user 100
- 假名沿用 `src/atg-core/tests/fixtures/basic.json`：user 101 林小雨、102 周大山、103 陈一一，会话 101、-1001 周末爬山群、-1002 示例频道。另加：user 100 是自己（名字编作「我自己」），105 名字还没到，106 和林小雨重名的另一个人，107 已注销，108 私聊对方信息还没到；会话 -1003 新建的群。这些都是编的

> **正例定方向，负例定护栏；正例给人看，负例给脚本查。**
>
> 「像不像好东西」判不了，「有没有犯这几条」判得了——**负例是把判好坏降级成判对错的那一步。**

## 风格档案怎么提取

**读每一处改动 → 让 AI 猜你的意图 → 分级（5 通用 … 1 一次性）→ 写清依据 → 决定去向。**

只留 4–5 级（跨项目通用的）进这里；1–3 级留在那次改稿的记录里。

## 铁律

- **人亲手改的那一版是原件**，AI 生成的更漂亮也只是参考——**人手为界**。
- 风格档案要**跟着作品更新**。真相源滞后，会把你的原话误判成 AI 自造，还漏掉真正的代笔。
- 空着比写错更危险：没有负例表，一切质检都只能靠「感觉不太对」。
