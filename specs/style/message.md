## 一、基本形状

### 例 M1 别人发的文字

夹具：消息 1001，发送人 user 102 周大山，正文「明天早上七点出发」，时间 19:30。

正例：

周大山：明天早上七点出发，19:30

反例：

周大山说，明天早上七点出发，今天 19:30

错在哪：「说」「今天」没有信息；R3 只读钟点，「今天」也算日期。

### 例 M2 自己发的

夹具：发送人 user 100，outgoing true，正文「好的，没问题。」，时间 19:31。

正例：

我：好的，没问题，19:31

反例：

我：好的，没问题。，19:31

错在哪：正文末尾的句号不去掉，会连停两次（原则「正文末尾」一条）。

### 例 M3 问号、叹号留着，后面不接逗号（V22）

夹具：发送人 user 101 林小雨，正文「几点出发？」，时间 19:32。

正例：

林小雨：几点出发？19:32

现状：

林小雨：几点出发？，19:32

反例：

林小雨：几点出发，19:32

错在哪：问号带语气，去掉就听不出是在问（原则「正文末尾」一条）。V22 人定问号、叹号后面直接接钟点，不再加逗号。

### 例 M4 格式和链接

夹具：发送人 user 103 陈一一；正文「看下路线图」，「看下」是粗体，「路线图」是文字链接，地址 https://example.invalid/route；时间 19:30。

正例：

陈一一：看下路线图，19:30

反例：

陈一一：粗体，看下，链接，路线图，https://example.invalid/route，19:30

错在哪：格式不读，链接只读文字不读地址（原则）。地址归「列出本条链接」。

### 例 M5 很长的消息

夹具：发送人 user 102 周大山，时间 19:30，正文是：

周六全天晴，最高气温二十三度，最低气温十一度，西北风三级，适合户外活动，请大家注意防晒补水。

正例：

周大山：周六全天晴，最高气温二十三度，最低气温十一度，西北风三级，适合户外活动，请大家注意防晒补水，19:30

反例：

周大山：周六全天晴，最高气温二十三度……按详情看全文，19:30

错在哪：R2 和原则都定了不截断，听够了人自己打断。

### 例 M6 附件

夹具：发送人 user 101 林小雨，附件 voice，duration 12，时间 19:34。

正例：

林小雨：语音 12 秒，19:34

反例：

林小雨：messageVoiceNote，19:34

错在哪：英文类型名不读，只进 JSON（原则）。别的附件的说法以快照 `src/atg-core/tests/snapshots/snapshots__basic_messages_brief.snap` 为准，本文不逐个重列。

### 例 M7 认识但还没做读法的内容

夹具：发送人 user 102 周大山，附件 other，td_type messageDice，时间 19:31。

正例：

周大山：暂不支持的消息，19:31

说明：以后做了骰子的读法再改，这一条不是错。

## 三、隐藏内容（R1、V13）

R1 的「按 D 展开」由调用方给键；没有键的（命令行）把「，按 D 展开」整段去掉。读法上下文现在还没有展开键这个字段，见缺口第 6 条。下面的「展开键 D」指调用方给了 D。

V13 人定：每处遮住的地方只读「隐藏内容」，「按 D 展开」整条只说一次，放在末尾、钟点前面。

回填推及，待人确认：只有一处遮挡时也照这个位置（M13、M14、M16、M17）；正文以问号、叹号结尾时，照 V22 不加逗号，直接接「按 D 展开」。例如正文「几点？」里「几点」是剧透、展开键 D、时间 19:32，读：

林小雨：隐藏内容？按 D 展开，19:32

（正文没被遮的「几点？」读成「林小雨：几点？按 D 展开，19:32」这种形状，只在别处另有遮挡时出现。）

### 例 M13 正文里有一段剧透

夹具：发送人 user 101 林小雨，正文「结局是凶手是管家」，其中「凶手是管家」是剧透实体；时间 19:33；展开键 D。

正例：

林小雨：结局是，隐藏内容，按 D 展开，19:33

没有展开键时（命令行）：

林小雨：结局是，隐藏内容，19:33

现状（现代码还没有展开键，和上一句相同）：

林小雨：结局是，隐藏内容，19:33

反例：

林小雨：结局是凶手是管家，19:33

错在哪：把遮住的内容读出来了，违反 R1。

### 例 M14 被遮住的图片，带说明文字

夹具：发送人 user 101 林小雨，附件 photo，spoiler true，说明文字「山顶的风景」，时间 19:33，展开键 D。

正例（按 V13 推及，键放在末尾，待人确认）：

林小雨：图片，隐藏内容，山顶的风景，按 D 展开，19:33

现状（现代码还没有展开键，也就是没有展开键时该读的样子）：

林小雨：图片，隐藏内容，山顶的风景，19:33

反例：

林小雨：图片，山顶的风景，19:33

错在哪：图片被遮住了却没说（R1）。说明文字没被遮，照读。

### 例 M15 一条里有两段剧透

夹具：发送人 user 101 林小雨，正文「甲是凶手，乙是帮凶」，「甲」「乙」各是一个剧透实体；时间 19:33；展开键 D。

正例：

林小雨：隐藏内容，是凶手，隐藏内容，是帮凶，按 D 展开，19:33

现状（现代码还没有展开键）：

林小雨：隐藏内容，是凶手，隐藏内容，是帮凶，19:33

反例：

林小雨：隐藏内容，按 D 展开，是凶手，隐藏内容，按 D 展开，是帮凶，19:33

错在哪：V13 人定整条只说一次。

### 例 M16 18 岁以上遮挡

夹具：发送人 user 102 周大山，附件 photo，content.sensitive true，时间 19:35，展开键 D。

正例：

周大山：图片，隐藏内容，按 D 展开，19:35

现状（现代码还没有展开键，也就是没有展开键时该读的样子）：

周大山：图片，隐藏内容，19:35

反例：

周大山：图片，敏感内容，19:35

错在哪：剧透和 18 岁以上遮挡统一叫「隐藏内容」（原则）。

### 例 M17 图片既是剧透、又是 18 岁以上

夹具：同 M16，另加 spoiler true。

正例（只说一次）：

周大山：图片，隐藏内容，按 D 展开，19:35

周大山：图片，隐藏内容，隐藏内容，19:35

## 五、发送人特殊的情况

### 例 M22 连续同一发送人（V8）

夹具：连着三条，发送人都是 user 102 周大山，时间 19:30、19:30、19:31，正文「明天」「早上七点」「北门集合」。

正例（每条都读名字）：

周大山：明天，19:30

周大山：早上七点，19:30

周大山：北门集合，19:31

反例一：

早上七点，19:30

错在哪：V8 人定不省名字。按 F2 落在第一条未读、或从搜索跳进来时，落点可能正好是这条，听不出是谁说的。

反例二：

周大山：明天，早上七点，北门集合，19:31

错在哪：三条合成了一项。每条消息是一个焦点，合起来就没法单独回复、删除其中一条（R6 同理）。

### 例 M23 重名（V9）

夹具：user 101 和 user 106 名字都是林小雨。user 101 发「我到了」，user 106 发「我也到了」，时间都是 19:40。两人的用户名假设是 example_a、example_b。

V9 人定：本会话里撞名时，名字后面接用户名；没用户名的不区分。用户名数据要等 #43，到之前一律不区分。

正例（#43 做完后）：

林小雨 example_a：我到了，19:40

林小雨 example_b：我也到了，19:40

现在（#43 做完前）快照填：

林小雨：我到了，19:40

林小雨：我也到了，19:40

反例：

林小雨（101）：我到了，19:40

错在哪：括号 VoiceOver 不念，数字 id 对人没有意义。

### 例 M24 用别的频道身份在群里发言

## 六、连续相同的表情（V12）

V12 人定：连续三个及以上相同的表情合并成「N 个某表情」；两个及以下、或不连续的照原样。只改名称，复制全文、阅读视图照原样（原文由 `plain_text` 出）。

回填推及，待人确认：会话项里的最后一条也照样合并，因为两处用的是同一套内容读法。

### 例 M29 五个一样的笑哭

夹具：发送人 user 101 林小雨，正文「😂😂😂😂😂」，时间 19:30。

正例：

反例：

林小雨：😂×5，19:30

### 例 M30 不连续、不一样的不合并

正例（最长只连着两个，不到三个，不合并）：

林小雨：好😂😂哈哈🤣😂，19:30

## 人定结果（2026-10-26）

记录正本：`docs/plan/007_decisions-b15.md`。每题留着题面、选项、代价，以后要翻案时查。V1 到 V7、V20 在 `chat-item.md`，V16 到 V19、V23 在 `service.md`。

### V8 连续同一发送人要不要省名字

题面：同一个人连着发几条，后面几条要不要省掉名字（例 M22）。

选项：A 每条都读。B 同一人、间隔不超过 5 分钟，后面的省名字。C 后面的把名字换成「接着」。

代价：B、C 每条省约 1 秒，但落点正好在省了名字的那条时听不出是谁说的。

人定 2026-10-26：A，每条都读。

### V9 重名怎么区分

题面：同一个群里两个人名字一样（例 M23）。

选项：A 不区分，详情里看用户名。B 只在本会话撞名时，名字后面接用户名。C 接「另一位」之类的序号说法。

代价：B 要成员的用户名（#43）；用户名里的下划线、字母，VoiceOver 会念「下划线」、可能逐个拼字母；没用户名的人仍分不出。C 的序号随加载顺序变。

人定 2026-10-26：B，撞名时接用户名。用户名数据是 #43，到之前照 A 不区分。

### V10 频道发的每一条要不要读频道名

题面：频道里每一条都是频道以自己名义发的（例 M26）。

选项：A 每条读频道名。B 不读，直接读内容和钟点。

代价：A 每条多读一遍频道名；B 句子形状和别处不同。

人定 2026-10-26：B，不读。

### V11 匿名管理员怎么读

题面：管理员以群的名义发言，发送人就是这个群（例 M25）。

选项：A 读群名。B 读「匿名管理员」。C 有署名读署名，没署名读「匿名管理员」。

代价：C 要 TDLib 的署名 author_signature，树里没有。

人定 2026-10-26：B，读「匿名管理员」。

### V12 连续相同表情要不要合并

题面：连着几个一样的表情（例 M29、M30）。

选项：A 不合并，原样交给 VoiceOver。B 合成「😂×5」。C 合成「5 个😂」。选 B 或 C 时，还要定连续几个起合并。

代价：A 五个就念五遍；B 的乘号念法没实测；C 是普通中文。

人定 2026-10-26：C，连续三个及以上合并，如「5 个😂」（人单独选）。
