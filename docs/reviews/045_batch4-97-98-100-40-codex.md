- **P1｜src/atg-core/src/secret.rs:61 清零前把长度设成容量，违反 `Vec::set_len` 前提**（第 1 轮 #1）
  - 核实：属实。容量区可能从没写过，`set_len(cap)` 后借成 `&mut [u8]` 是未定义行为，事后写零补救不了
  - 处理：`wipe_all` 长度不动，`0..len` 用 `wipe`，容量区用 `spare_capacity_mut()` 逐格 `write_volatile(MaybeUninit::new(0))`；原测试照过
- **P1｜src/atg-cli/src/signals.rs:30 恢复终端与切换终端没有互斥**（第 1 轮 #2）
  - 核实：属实。进程收的信号可落在 TDLib / 收线程上：处理函数先放回终端，主线程随后切成不回显，再 `_exit`，终端停在不回显；撤销后重新登记时也可能与处理函数读 `SAVED` 竞争
  - 处理：`signals.rs` 加原子自旋锁 `TTY_LOCK`。「登记 + 切」（`arm_tty` 收闭包）与「放回 + 撤销」（`disarm_tty` 收闭包）各在锁里一段做完，期间本线程 `pthread_sigmask` 挡 SIGINT / SIGTERM（本线程的处理函数不会撞上自己攥着的锁）；第二次信号的处理函数先抢锁再放回、`_exit`，抢到不放。补测「锁被占着时登记等它放开」。codex 建议的子进程真发信号时序测试未做：时序窗口在微秒级，造不稳定，靠锁的不变式与单测
- **P1｜src/atg-core/src/config.rs:388 判「不新」时仍可能误报 missing**（第 1 轮 #3）
  - 核实：属实。A 读到缺 → B 建好档案并 `lock()` 建了 `atg.lock` → A 的 `is_fresh` 看到锁文件判不新 → 报 `profile_marker_missing`
  - 处理：抽出 `on_missing`：新的写标记；不新的再读一次标记，在了就按它走（随后 `open` 核种类），仍缺才报 missing、读不懂报 unreadable。`config.rs` 内补两条单测（有标记 + 锁 → 不报；只有锁 → 仍报 missing 且不补写）
- **P2｜src/atg-cli/src/tty.rs:153 fd ≥ FD_SETSIZE 时退回无期限 `read`**（第 1 轮 #4）
  - 核实：属实。继承的描述符多时 `/dev/tty` 的 fd 可能超过 1024，此时不看停止标志，SIGTERM 收不了尾
  - 处理：留作 issue #116（macOS `poll` 不支持终端，要换 kqueue 或放大 `fd_set`，属另一件事）
