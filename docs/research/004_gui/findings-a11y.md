## 〇、结论先行（十条）

1. **macOS 原生没有 live region**，主动说话只有一条正路：对应用元素发 `AnnouncementRequested`，带文字和优先级（10 / 50 / 90）。头文件原话：VoiceOver 按优先级决定「立刻说」还是「等当前说完」（`AXC.h:606`、`:621-626`）。· SDK
2. **礼貌式不可靠地等**：专家 2026-01 实测 macOS VoiceOver 下 polite 会插话、assertive 会打断并终止朗读（Roselli-2026），与本项目 exp001 人工试听一致。对应关系（下面这句是**推断**，排队行为未确认，10 只是**最值得优先实验**的一档，50 在某些条件下是否排队也未排除）：网页 polite / assertive 由浏览器翻成 macOS 公告，WebKit 的映射细节未查，按实测表现看 polite 未必是「等说完」；而 macOS 原生只有 10 / 50 / 90 三档，头文件只说「按优先级决定立刻说还是等」，iOS 侧讲 high 打断、low 排队——所以**低优先级 10 是最可能排队的一档**（「排队」指 VO 收到后等当前朗读说完），要人试听确认（exp004 模式 2 =「最低优先级立刻说」，`docs/experiments/exp004-announce-calm/`）。· 专家 + 实测（polite 会插话）+ SDK（头文件措辞）+ 推断（10 会排队）
3. **焦点变化那一刻发出的公告常被吞**：公告要错开焦点移动。· 社区（WebKit-222190、apple-ax-dev-2013）
4. **消息列表最像 APG 的 feed**（流式、虚拟化、焦点驱动加载、批量加载时 busy），会话列表最像 listbox；消息里的链接 / 附件：APG 的「布局 grid」（→ / Return 进、Esc 出）是先例，**本项目现行按 `specs/gui/keymap.md`：`l` 打开链接列表、`o` 打开附件、Esc 回去**。· 文档（APG）+ 推断
5. **active-descendant 与 roving 二选一、不混用**；虚拟化下 active-descendant 更合适。它的三个风险点里，VO 光标跟随这一路：通知会发出（读源码），macOS 层焦点元素正确（exp003 实测，GPUI 内模拟按键），VO 实际跟读由人试听过 exp003b-v2 交互并认可（`docs/plan/003_decisions-b2.md` 第 66 行）；**缩放跟不跟、语音控制点不点得到可见行还没测**。· 文档 + 社区 + 读源码 + 实测（含人工试听）+ 推断
6. **业界：次要操作走「自定义动作」**（VO-Cmd-Space 打开），**按类跳走「自定义转子」**（未读 / 提及 / 链接 / 附件）。· 文档。**但 ggpui 读源码确认这两样目前在 AccessKit 的 macOS 适配层都没有**（第一节第 4 小节）→ 标准照列：自定义动作标「需补丁」（补丁编号 P1，编号空间见 `specs/gui/README.md` 第二节，不是评审等级），转子标「实验候选」（P15：窗口上挂转子，不是补丁）；另配应用快捷键 + 菜单栏项。
7. **VoiceOver 占 Ctrl-Opt 一族**作自己的命令；快速导航开着时吃单独方向键和单字母。· 文档。**人定（013 B19-3、B19-4）**：快速导航由人使用时自己关掉，不为它绕路；快捷键首选**单键（像 Slack）或 Cmd + 键**，Ctrl-Opt 可用但不作首选。单键只在列表获焦、不在文本框、不在输入法组字时生效（这本身就满足 WCAG 2.1.4）。
8. **「键盘焦点跟随 VO 光标」开着时，VO 路过就会把焦点拉过去** → 获焦不能有副作用（不因路过就标已读、自动播放）。· 文档 + 推断
9. **读屏以外的辅助技术都靠同几样东西**：每个可操作元素有 press 动作、frame 正确、名称以可见文字开头、组有名字且层级浅。语音控制、切换控制、全键盘访问、缩放、盲文都吃这一套。· 文档
10. **agent 友好 = 角色 + 名称 + 状态属性 + 稳定标识 + 动作**：Playwright、MCP 都已拿「无障碍快照 + 稳定引用」当 agent 主接口；标识要写死、跨语言不变、只增不改。· 文档 + 推断

### 2. VoiceOver 读法顺序与名称写法

- 顺序：**名称 → 值 → 角色名 → 状态（已选中）→ 停一下读提示（help）**。提示读不读由用户的「详细程度 › 提示」决定，VO-Shift-N 可主动听。· 文档（VO-general）
- 行：VO 把行内子元素的字串起来读，**子元素顺序就是读的顺序**；要控制读法，最稳是给行一个完整名称、子元素不重复读。· 推断（业界常见）。本项目已这样做：每项名称取 `speech` 的 brief（001 第二节第 1 小节）
- 名称写法（Apple 归档指南 AXMacOSX-guide）：短、说「是什么」、**不含角色词**（写「发送」不写「发送按钮」）、不加句号、要本地化。提示只在结果不明显时写，以动词开头、省主语。· 文档
- **名称以可见文字开头**（WCAG 2.5.3），否则语音控制用户说可见文字点不到。· 文档
- 盲文显示器常见 40 方：**区分信息放名称最前**（人名、未读数），首段就能分辨。· 文档 + 推断

### 3. 通知：什么时候发

| 通知 | 何时 | 出处 |
|---|---|---|
| `FocusedUIElementChanged` | 键盘焦点换元素 | SDK |
| `SelectedRowsChanged` / `SelectedChildrenChanged` | 表格 / 非表格容器的选中项变 | SDK |
| `ValueChanged` | 值变（输入框、静态文字内容） | SDK |
| `TitleChanged` | 窗口标题变（写进「N 条新消息」时，001 第二节第 2 小节） | SDK |
| `RowCountChanged` | 行数变（新消息、加载更早、会话增删） | SDK |
| `LayoutChanged` | 面板出现 / 消失；可带改变的元素 | SDK |
| `Created` / `UIElementDestroyed` | 元素出现 / 销毁；不发销毁 VO 会拿着悬空引用 | SDK（通知）+ 推断（后果） |
| `TextInputMarkingSessionBegan/Ended` | 输入法组字开始 / 结束 | `AXC.h:466-467` · SDK |
| `AnnouncementRequested` | 主动说一句；对**应用元素**发；userInfo 必带文字，**每次都应带优先级** | `AXC.h:494`、`:606-626` · SDK |

- 优先级取值 `Low=10 / Medium=50 / High=90`（`AXC.h:624-626`）· SDK
- 语义：头文件说由读屏「按优先级决定立刻说还是等当前说完」（`AXC.h:606`）；iOS 侧 WWDC 讲 high 打断、low 排队（WWDC23-10036）；**macOS 上各档到底打不打断，Apple 没写清**；Firefox 报告 medium 改 high 后会自我打断（Mozilla-1888310）。· SDK + 文档 + 社区

### 4. 自定义动作与自定义转子

- **自定义动作** `NSAccessibilityCustomAction`：给元素挂一组带名字的动作（回复、转发、复制、删除、标已读、播放），VO-Cmd-Space 打开动作菜单。名字照名称规范、用动词。· 文档（AppKit-customaction）
- **自定义转子** `NSAccessibilityCustomRotor`（10.13+）：容器挂「未读」「提及」「链接」「附件 / 语音」转子，VO-U 打开、左右换转子、上下走条目；**条目可以还没建 UI**（有加载委托），正好补虚拟化的缺口。预置类型里有 Link、Heading 等，用预置类型 VO 能接上已有快捷键（VO-Cmd-L）。· SDK（`NSAccessibilityCustomRotor.h`）+ 文档
- 例证：Apple 的 SwiftUI 转子文档就拿邮件 / 消息应用做例子（VIP 来信）。· 文档
- ⚠️ **ggpui 已核（读源码，2026-11-14，详见 `findings-gpui.md` 第 2.4、8 节）：两样在 macOS 上目前都走不通。** 自定义动作：AccessKit 的节点能存，但 macOS（以及 Windows、AT-SPI）适配层没有读它，写了 VO 也看不到；自定义转子：AccessKit 没有这个概念。ggpui 的建议：动作先给 AccessKit **开 issue** 附对照证据（AccessKit 不收外部 PR，`findings-gpui.md` 第 8 节与 sources G11），按维护者反馈再推进补丁（属 `.42cog/intent.md`「不做什么」现行措辞：缺口打小补丁并提交回上游）；转子先试挂在窗口上（实验候选），而且屏外的项还没进树，转子「懒加载补虚拟化」只能补一半。
- **标准不降**：人定「GPUI 无障碍有缺口就自己打补丁，做好后提交回上游」（013 B19-1）。所以自定义动作、自定义转子照「应该长什么样」列为要求：动作标 **「需补丁」**（P1），转子标「实验候选」（P15），方案归 ggpui（编号见 `specs/gui/upstream-patches.md`）。补丁落地前，**另外**要有应用快捷键 + 菜单栏项（这本来就该有：单键快速导航开着时收不到单字母，菜单项对 VO、语音控制、切换控制、agent 都可达），不是替代。· 推断
- 正本已跟上：`.42cog/intent.md`「不做什么」已按 013 B19-9 改为「无障碍缺口直接打小补丁……同时提交回上游，不维护长期私有分支」，补丁清单正本 `specs/gui/upstream-patches.md`（gssot）。

### 与已拍板的对照（不改拍板，只列出供 gssot / 人参考）

- **列表角色**：人选了「普通列表」（001 第七节第 1 条，2026-10-25）。业界原生应用多用 table。差别：table 有 `SelectedRowsChanged` / `RowCountChanged`，VO 会报「第 x 行共 y 行」——而人**明确不要位置**（001 第二节第 1 小节「不读第几条共几条」；第七节第 2 条只管列表名）。**结论：不构成推翻理由**，记作「若以后要行数通知再议」。
- **位置属性**：APG feed 要求每条带位置和总数；人定不读，但树里照设（001 第二节第 1 小节）——与 feed 的「给 agent 读」那一半一致，不冲突。

## 二、ARIA 编写实践（APG）可借的模式

> ARIA 角色最后也映射成 AXRole，模式可借；但浏览器特有的坑（Safari 的映射 bug）不一定在原生上复现，反之亦然。

### 1. 模式对照

| 模式 | 键盘约定 | 借给本项目的哪块 | 出处 |
|---|---|---|---|
| **listbox** | ↑/↓、Home/End、首字母跳转；单一 Tab 停靠 | **会话列表**。APG 明说 option 只能是纯文本，带按钮链接的条目不适合 | APG-listbox · 文档 |
| **feed** | PageUp/PageDown 在条目间移动，Ctrl+End / Ctrl+Home 跳出到前后；每条带位置与总数（总数未知 = -1）；批量增删期间 `busy`，**结束务必复位**；加载由「哪条有焦点」驱动；因无通行惯例，**快捷键要写成好找的说明** | **消息列表的语义**：焦点驱动加载更早、批量加载标 busy、明确的跳出键 | APG-feed · 文档 |
| **布局 grid** | 一个 Tab 停靠；方向键走格；Return / F2 进格内控件、Esc 退出 | 先例：消息内的链接 / 附件 / 按钮「选中消息 → → 或 Return 进入 → Esc 回列表」、不进 Tab 序列。**本项目现行按 `keymap.md`（`l` / `o`），只借「不进 Tab 序列、Esc 回原消息」** | APG-grid · 文档 + 推断 |
| treegrid | →/← 展开收起 | 话题 / 评论串（第一阶段不做） | APG-treegrid · 文档 |
| **dialog（模态）** | Tab 在框内循环；Esc 关；开时焦点进框；**关后焦点回触发处**，触发处没了就去逻辑上的下一处 | 转发选人、设置 | APG-dialog · 文档 |
| **alertdialog** | 同 dialog；正文打开即读；**默认焦点放最不具破坏性的按钮**（取消） | **发送确认**（001 第四节第 1 小节）、删除确认。要人回应的事一律不用公告 | APG-alertdialog · 文档；Soueidan-2 · 专家 |
| **combobox** | 焦点一直在输入框；↓ 进结果；↑/↓ 移；Return 采纳；Esc 关 / 清；高亮项用输入框上的 active-descendant 指出 | **搜索（T08）**、快速切换会话、@ 提及补全 | APG-combobox · 文档 |
| toolbar | 单停靠，←/→ 走按钮，Home/End | 输入框旁的附件 / 格式按钮条 | APG-toolbar · 文档；Slack 2022 改版即此 · 社区 |
| menu | 开时焦点进第一项；↑/↓；Esc 关并回触发按钮 | 消息右键菜单、附件菜单。原生 macOS 首选系统菜单 | APG-menu · 文档 + 推断 |
| tabs | ←/→ 切换 | 会话过滤（全部 / 未读）、表情分类 | APG-tabs · 文档 |

**live 区域角色语义**（用来定「哪种变化该说、哪种不该说」，原生上全部落到公告）：

- `log`：按顺序追加、旧的有意义，W3C 拿聊天记录当例子，隐含礼貌式。`status`：建议性，隐含礼貌 + 整块读，不获焦。`alert`：重要且紧急，隐含打断。`timer` / `marquee`：**默认不播**（计时器、滚动字）。· 文档（ARIA-1.2）+ 专家（OHara-2022）
- `busy` 期间的变化先不入队，清掉 busy 再处理。实现指南允许打断式进来时清掉排队的礼貌式。· 文档（MDN）
- 播报区域越少越好，「太多和没有一样糟」；必须事先存在再填内容。· 专家（OHara-2022）

### 2. 两种焦点模型

| | roving（真焦点在子项上） | active-descendant（焦点在容器，指针指子项） |
|---|---|---|
| 读屏兼容 | 最广、最稳 | 历来参差，尤其 Safari + VO（WebKit 自 2017 起一串 bug：移动时不读出项；主跟踪 bug 称 Sequoia 15 修复，2024 仍有不读的报告） |
| 虚拟化 | 焦点项必须钉住不被回收 | 只需被指的那项在树里，容器永驻 |
| 打字不丢焦点 | 不行 | 行（combobox 靠它） |
| 缩放跟随 | 天然跟 | 可能只跟容器 |
| 语音控制 | 子项天然可点 | 子项也要有名称、可按下 |

出处：APG-keyboard · 文档；WebKit-167680 / 269026 / 209076 · 社区；Roselli-2026、Zellwk · 专家 / 社区；LevelAccess（语音软件忽略 ARIA）· 专家。

- **不混用**：子项可聚焦的同时容器又设 active-descendant，会互相打架。· 社区（Evinced）
- **折算到原生**：WebKit 的坑在「把 active-descendant 翻译成 NSAccessibility」那一层；业界原生的通常对应物是「容器报选中子项 + 对子项发焦点变化」；**但本项目的 GPUI 不是这样**：它在帧末把 AX 焦点直接换成当前项（`findings-gpui.md` 第 200 行，读源码），普通列表在 macOS 层也没有「行 / 已选子项」属性（exp003 README 第 68 行，实测）。三件事要分清：键盘焦点留在列表容器（GPUI 内部）、AX 焦点落在当前项（VO 看到的）、selected 属性在当前项上。本项目这一路的证据分三层：AccessKit 发 `FocusedUIElementChanged` · 读源码（`docs/research/001_stack/findings-gpui.md` 第 2 条）；每步在 macOS 层主动查焦点元素，标题与选中都对 · 实测（exp003，1137 步，GPUI 内模拟按键、未经 AppKit 与输入法，见 `docs/experiments/exp003-list-nav/README.md`）；VO 实际跟读 · 人工试听（003 第 66 行）。**还没测的**：缩放跟不跟、语音控制能不能点到可见行。
- **判断**：消息列表、会话列表维持 active-descendant（已在 exp003b-v2 跑通）；搜索：APG combobox 的「焦点留在输入框 + active-descendant」在 GPUI 上做不出（卡 G17），**现行按清单 K14：↓ 把焦点移进结果列表**；工具栏、菜单、标签用 roving。· 推断

### 2. 基本键惯例

- **Esc**：关弹层、取消、退出当前模式；不清草稿。· 文档（HIG-keyboards）+ 推断
- **Tab / Shift-Tab**：区块间移动，列表内部不靠 Tab 逐行走。· 文档（HIG-focus）——与 001 第二节第 4 小节的 Tab 一圈一致
- **方向键**：列表内移选中；Cmd-↑/↓ 到顶底是 macOS 惯例。· 社区
- **Return**：输入框里发送（Shift-Return / Opt-Return 换行）；列表里打开；对话框里按默认按钮。· 文档 + 社区
- **Cmd-1…9**：各家聊天应用拿来切第 N 个会话或工作区，空闲可用。· 社区

### 3. 聊天应用的共识快捷键（Slack / Discord 对照）

Cmd-K 快速切换 · Opt-↑/↓ 上 / 下一个会话 · Opt-Shift-↑/↓ 上 / 下一个未读会话（⚠️ 与文本按段扩选同键，本项目不照搬，见第七节 T09） · Esc 标当前会话已读 · Cmd-/ 快捷键表 · F6 键区块循环（键名，不是拍板 F6）· 消息上的单字母（e 编辑、r 回复）**只在消息获焦时**生效。· 社区（Slack-shortcuts、Discord-shortcuts）

### 4. 单字母快捷键（如 m 收听、D 听详情）什么时候安全

WCAG 2.1.4（A 级）：只用字符键的快捷键必须**可关闭、或可改成带修饰键、或只在相关组件获焦时生效**，三者其一。· 文档（WCAG-2.1.4）

本项目叠加条件（推断，依据上面两节）：

1. 只在**消息列表或会话列表获焦**时生效
2. 焦点在任何文本输入元素里时不生效
3. 输入法**正在组字**（有标记文本）时绝不截
4. 每个功能都有菜单栏项（给语音控制、切换控制、agent 用；**不是**为快速导航绕路——人定快速导航使用时关，013 B19-3）
5. 设置里有总开关（WCAG 2.1.4 三选一里，第 1 条「只在获焦时生效」已满足，总开关是加分项）

**人定的快捷键取向**（013 B19-4）：像 Slack，首选单键或 Cmd + 键；Ctrl-Opt 可用不首选。与第 3 小节共识对照：Slack 自己的跳未读是 Opt-Shift-↑/↓，不是单键——这类「任何焦点下都能按」的全局键（T09）用修饰键组合，且不能落在文本编辑键族里，单键留给列表获焦时的操作（m 收听、D 详情、r 回复……）。· 推断

### 5. 输入法

- 组字期间 Return 是上屏、Esc 取消、数字与空格选词、方向键在候选窗里走；**Return 发送必须先判有没有标记文本**。经典事故：中文用户回车选英文，消息被发出去。· 文档（NSTextInputClient）+ 社区
- 组字开始结束有 `TextInputMarkingSession*` 通知（`AXC.h:466-467`，只证明常量存在）· SDK。它是不是 VO 读候选的必要条件**待核**：候选窗由系统输入法提供（`findings-gpui.md` 第 208 行），实际朗读要人试。· 推断
- 与 001 第二节第 1 小节对照：「Tab 任何时候截、↑/↓ 只在列表获焦时截、输入框里的方向键留给输入法」——**与业界一致**；补一条：**列表获焦时也要先判有没有标记文本**（双拼会不会在没有输入框时认领方向键，R3 还没测）。

### 6. VO 光标与键盘焦点

- 「键盘焦点跟随 VO 光标」开着时，VO 走到可聚焦元素就把焦点拉过去（默认值子代理 A 记为开，**未逐字核对官方原文**）。· 文档 + 待核
- 推论：**获焦不能有副作用**。人定「标已读不算红线」（N3，`docs/plan/005_decisions-b3.md`）管的是开发测试许不许，**不是**交互上「选中即标已读」好不好——这一条要 gssot 定交互时注意。· 推断
- 触控板手势（Trackpad Commander）作用于 VO 光标、不经应用按键处理 → 所有功能都要能用 press / 自定义动作完成，不能只绑键盘事件。· 文档 + 推断

### 1. 一句话现状

- **Telegram macOS 原生版**：VO 下基本不可用（用户报告「什么都认不出」、验证码栏输不进）；官方仓库已搜不到，看不到实现。第三方原生客户端在补，但有「新消息要切会话才刷新」的报告——**正落在真难题 1 上**；所查样本（官方 mac 版、两款第三方原生客户端，均为社区报告，未亲测）里，**还没有证据表明哪一个已满足真难题 1**。· 社区（2024–2026）
- **Telegram Desktop（Qt）**：2026 年社区补了较完整的读屏支持（部分 PR 未合并，主要在 Windows + NVDA 上测），**本轮最值得对照的先例**。· 他源（tdesktop PR #30306 等）

**Telegram Desktop 的一句话顺序**（他源，`history_inner_widget_accessibility.cpp`）：自己发的先读已读状态 → 发送人 → 经由机器人 → 「回复 X：原文」→ 转发来源 → 媒体类型与要素（语音读「未播放」）→ 链接预览 → 正文 / 说明 → 置顶 → 状态（发送中 / 失败）· 已编辑 · 时间 · 浏览数 → 回应。它把状态压在自己消息的最前面，**这一点不该学**。

### 3. 可借的（对本项目）

1. **焦点按身份、不按下标**——与 001 第二节第 1 小节「元素 id =（会话 id，消息 id）」一致；补：reducer 测试里加「新消息 / 删除 / 加载更早后，选中项身份不变」（001 第四节第 2 小节已有前两样）
2. ~~已读由读到决定~~ **人已定不采用**（013 B19-2：维持拍板 F1，进会话直接标已读到最新）。留作对照：tdesktop 让选中（被读到）才算已读、滚动不算。本项目只借其中「获焦本身不产生副作用」这层（第三节第 6 小节）
3. ~~未读分隔线是可聚焦地标~~ **人已定另一做法**（013 B19-7）：分隔线**不进 ↑↓ 顺序、不可停**；进会话落在第一条未读（拍板 F2 字面），其名称前加「未读：」。借的只剩「不自动消失」——分隔的位置信息由这个前缀承载
4. **重放而不移动焦点**（Slack Cmd-Opt-数字）——与本项目「按 m 收听」同一思路；可扩成「m 听新消息汇总、Cmd-Opt-1…9 重放最近第 N 条」
5. **详略与顺序交给用户**：默认分层（brief / detail，001 第三节），以后给开关
6. **一句话 + 按需展开**：brief 一句，detail 按键展开（001 第三节）；tdesktop 的「字段子项」对 agent 有用（字段即属性）
7. **回应只报汇总**（「回应：👍 3」）——**只放 detail 层**（人定 003 R5：回应不进名称）；谁回应的也在 detail
8. **明说「回复」二字**（「回复 X：原文摘要」），不让原文和回复连读——**只放 detail 层**（人定 003 R4：回复 / 转发不进名称；`specs/style/message.md` 例 M8 把名称里带「回复」列为反例）
9. **跳转后焦点落目标消息**（跳最新、跳引用原文、跳置顶）。加载更早：GitHub-timeline（2026-10）播「已加载 N 条」并把焦点放到新加载那条——**人定不采用**（013 B19-12：选中项原地不动，不播报）
10. **跳未读配快捷键**：本会话第一条未读、下一个未读会话、全局未读一句话

### 4. 要避开的坑

1. **会变的东西进播报**：相对时间、播放进度、当前时间（Signal、Element）
2. **「跳到」只滚动不移焦点**（Discord）
3. **列表一变焦点跳出、回来不记原位**（WhatsApp Mac、Telegram iOS）
4. **跳转后把焦点拽进输入框**（Element 修前）
5. **每条拆成一堆可聚焦元素**（Discord）——主元素一句话读完
6. **不合规的表格 / grid 结构**（Signal 用了 grid 却没有行和格，VO 进不去）——角色用对、结构完整
7. **不读发送人、回复不说「回复」**（Signal）
8. **状态压在内容前**（tdesktop 自己的消息）
9. **大量历史下无障碍查询平方级**（tdesktop PR #31432：6705 条一次查询 6.1 s，缓存后 39 ms）——本项目虚拟化只渲染可见项，问题小，但树导出与 agent 查询要量一次
10. **只在 Windows + NVDA 上测**——macOS VO 必须单独验

### 5. Quill（GPUI 写的 Telegram 桌面客户端，MIT）

> 仓库 MAIN `resources/quill-20261114/`（HEAD `d4a18b7`，大总管转来，gcomp 拉）。下文路径相对该目录。全部**读源码**（子代理只读，没编译没运行），另标的除外。它是与本项目同栈（GPUI + AccessKit 0.24.1 / accesskit_macos 0.26.3）的最近先例。

**现状**：VoiceOver 实际朗读仍是**手动待办**（`STATUS.md:1173` 未勾、`ROADMAP.md:194`「需要 Mac」）；它把「树和原生动作已验证」与「VO 实际怎么读未验证」明确分开——与本项目「验证红线」同一思路。· 读源码（Quill 自己的 STATUS / ROADMAP）

**做对的（可借）**

1. **读法是纯函数独立成模块**：一条消息 + 调用方算好的上下文 → 一句话（`src/message_a11y.rs:14-38`），顺序照 Telegram Desktop 移植。与本项目 `atg-core::speech` 同构
2. **消息列表 = 容器持真焦点 + 当前行 active-descendant**；焦点移到屏外先滚再量（`src/ui/history_a11y.rs:185-226`、`src/ui/conversation/history_message_list.rs:761-777`）。与 exp003b-v2 同一路，**同栈旁证**
3. **进会话落点规则**：保留原来那条 → 未读分隔之后 → 最新（`history_a11y.rs:116-125`）；未读分隔条本身能当 active-descendant（`src/ui/conversation/mod.rs:403`）
4. **只在读屏开着时接管 ↑/↓、Space**（`isVoiceOverEnabled` + 系统激活标志双判，`src/screen_reader.rs`、`history_a11y.rs:149-155`）。⚠️ 与本项目取向不同：本项目方向键对所有人都由应用处理（001 第二节第 1 小节），且第一节第 5 小节「不因 VO 开没开给不同功能集」——**它的做法只借「按键行为对不开读屏的人不变」这层意思，不借分叉**
5. **原生 AX 冒烟脚本**：「任何没名字的控件就失败」+ 真 AXPress / AXValue 往返（`scripts/macos-accessibility-smoke.sh`）——正是清单 S1、X1 的机判写法
6. **快捷键唯一正本**：绑定和帮助页读同一张表（`src/ui/shortcuts.rs:1-5`）——清单 K3
7. **焦点归还写成窗口测试**：关菜单 / 面板后焦点回原处、Tab 困在菜单里（`src/ui/context_menu_focus_tests.rs` 等）——清单 F7
8. **输入法**：回车那一刻读标记文本范围，组字中不发送（`src/composer/send.rs:51-63`）——清单 K6
9. **缓存视图的 a11y 洞**：GPUI 缓存视图不回放自己那部分树，一建树就逐帧全量渲染（空闲 CPU 15% → 25%），它打了补丁（`docs/decisions/a11y-cached-views.md`、`third_party/gpui-pre/QUILL-CHANGES.md`）——**本项目用缓存视图前要 ggpui 查有没有同样的洞**

**做错 / 没做的（要避开）**

1. **以为 `Status` / `Alert` 角色会自动念**：AccessKit macOS 只在节点设了 live（默认 off）且有 value 时才发公告（`accesskit_macos-0.26.3/src/event.rs:236`），它的提示框大概率是哑的。· 读源码 + 推断。**全仓没有主动播报**；STATUS 打了勾的「播报」实际写着 deferred
2. **读法只有一档全文**，已读回执在最前、时间倒数第二，每条听一长串；**硬编码英文**；只有 4 条断言、没有快照测试；**没有 emoji 的表情回应被悄悄丢掉**（`src/message_a11y.rs:154-173`）
3. **会话列表弱**：每行是按钮，名称只有「标题 — 预览」，没有未读数、静音、置顶；未读角标有名称没角色，进不了树；键盘选中不报给 AX（`src/ui/` 会话行，· 读源码 + 推断）
4. **不给位置与总数**（`src/ui` 里零处）
5. **只有当前行进树**：树小，但语音控制「显示编号」、切换控制、agent 都看不到其他可见行——与本项目清单 S18、X5、AG6 冲突，**不借**。· 推断
6. **减少动态效果只在启动时读一次**（起子进程跑 `defaults read`），高对比只是手选主题、不跟随系统
7. **实质性 fork GPUI**（vendor 后改，`third_party/gpui-pre/QUILL-CHANGES.md`）；**自定义动作（`on_a11y_action` 用 0 次）、转子、播报都没做**
8. **读屏开着时拒绝 agent 驱动**（`docs/decisions/agent-access.md:382-403`）——两类读者不能共用一棵树，与 `.42cog/cog.md`「一棵无障碍树，两类读者」相反

**agent 接口**：本机 socket（0600 + 同 uid + token）连进运行中的客户端，读同一棵 AccessKit 树；节点 id「元素在屏上时稳定」，另加**只给进程内读者、不发给系统**的 `a11y_tag`（如 `chat=<id>`）；按授权裁剪树（`docs/decisions/agent-access.md:703-758`、`src/ui/agent_driver_tree.rs:1-6`）。对本项目：机读标识本项目走 `AXIdentifier`（第六节），**进程外**的 computer use 也读得到，比它的进程内 tag 适用面宽；它的「按授权裁剪树」思路可供隐私（`.42cog/real.md`）参考。

**一句话**：Quill 在键盘、焦点归还、输入法、正本这些「机器能判」的层面扎实，在**播报、分层读法、会话列表、VO 实测**这些真难题上是空白——正好是本项目要做的。

## 五、播报礼仪

### 1. 规矩

- **默认不打断**；打断式只给紧急、要马上处理的事（连接断开、发送失败）。· 文档（ARIA-1.2 alert）+ 专家（Soueidan-2）
- 在 macOS VO 上打断式是「**打断并终止**」当前朗读，不是读完再续，代价比想象大。· 专家（Roselli-2026）
- **要人回应的不用公告**，用 alertdialog 或焦点管理；能用状态属性表达的（选中、展开）不播。· 专家（Soueidan-2）
- 公告要**短、一次写完整句、不含可交互内容**。· 专家（Soueidan-2）
- **节流**：高频变化（搜索结果数）防抖约 300–500 ms；两次公告间隔约 350–500 ms。经验值，不是标准。· 专家（Soueidan-2）
- **错开焦点变化**：焦点移动那一刻发的公告常被吞。· 社区（WebKit-222190、apple-ax-dev-2013）
- **中间态不播**：流式增长的内容（转写进行中、对方编辑中）稳定后整句播一次。· 社区（azukiazusa）——对本项目的转写节点（#59）直接适用
- **集中一处发**：一两个出口比各组件各自散放可预测。· 社区
- **去重 / 合并有现成语义可抄**：Windows UIA 通知的「处理方式」有 全部重要 / 只留最新 / 当前说完再说最新 等几种，外加「活动类别 id」让同类互相替换。· 文档（UIA-notification）
- **刷屏汇总**：快速来消息合并成「某群 5 条新消息」；当前打开且正在浏览的会话才读正文，其余只报计数。· 推断（业界常见，无权威出处）
- **用户正在操作时延后**：macOS 没有公开的「VO 正在说话」查询；代理信号是「最近 N 秒有按键或焦点移动」。· 推断——与 001 第二节第 2 小节「停手后」一致；注意 VO 组合键到不了应用（exp004 结论 4）
- **可配置详略**：Slack 让读屏用户自定义元数据朗读顺序；Apple 在 VO 转子里给了「实时区域与通告」开关，说明系统层允许整体关掉，应用应尊重并自带一层控制。· 社区（Slack-2022、AppleVis-189312）

## 六、agent 友好

- **稳定标识**：Apple 把 `accessibilityIdentifier` 定为给测试定位用、VO 不读，可以放机读 id（如 `msg:<会话>:<消息>`）。坑：合并或隐藏子元素后，标识要放在 VO 实际看到的那个元素上。· 文档（WWDC23-10035）+ 社区（Apple 论坛）
- 微软 AutomationId 只要求兄弟间唯一、不保证跨版本稳定 → 本项目要更强：**写死在代码、跨语言不变、版本间只增不改**。· 文档（UIA-automationid）+ 推断
- **按角色 + 名称定位**是测试与 agent 的首选（Playwright getByRole）；角色错了本身就是 agent 不可用。· 文档（Playwright-locators）
- **无障碍快照当回归**：Playwright 把树导成 YAML（角色、名称、状态）做对比——正对应本项目「改 GUI 必附树导出对比」。· 文档（Playwright-aria-snapshot）
- **快照 + 引用是 agent 主接口**：Playwright MCP 默认给模型无障碍快照而非截图，每个元素带引用，页面一变引用作废要重取。· 文档（Playwright-MCP）
- **状态走属性，不只写进名称**：选中、展开、忙、禁用。**例外：未读数**——macOS 没有对应 AX 属性，写进会话项名称（正本清单 AG4 / S19）。另外展开、忙在 GPUI 层有、到 macOS 层会丢（`specs/gui/upstream-patches.md` P2 等），agent 读 macOS 层时只能靠选中、禁用。· 推断（依据 APG 各模式）+ 读源码（ggpui）
- **名称可区分**：多条「好的」要靠发送人 + 时间或标识区分；每行一个「回复」按钮要靠父级或标识区分。· 推断
- **动作明确、不靠悬停**：回复 / 回应 / 转发走自定义动作；只在悬停时出现的操作条，agent 与键盘用户都摸不到。· 文档 + 推断
- **虚拟化对 agent**：只渲染可见项 → agent 看不到全量；列表上要暴露总数 / 位置（本项目已照设），并提供可调用的「滚到某条 / 加载更早」动作，而不是让 agent 靠滚轮坐标。· 推断（参照 feed）
- **与已有对照**：001 第二节第 1 小节已定「元素 id 从根到它整条路径稳定、列表 id 带会话 id」——这是 GPUI 节点身份，**与上面的「机读标识」是两件事**：节点 id 是 AccessKit 内部数字，agent 跨次运行拿不到同一个；要不要另设可读标识（`AXIdentifier` 一类）。ggpui 已核（读源码）：GPUI `div.rs:1373` 的 `.accessibility_id()` 写进 AccessKit，accesskit_macos `node.rs:502-508` 映射成 `accessibilityIdentifier`，进程外的 AX 客户端读得到；VO 不读它；只有进了树的元素才有，屏外项同样没有。→ **建议另设机读标识，走这个出口**，格式由 gssot 定进 `specs/gui/`。· 读源码（ggpui）+ 推断

### F1「进会话就把已读标到最新一条」与「获焦无副作用」：冲突吗

- **不必然冲突**：F1 管的是「进会话」这个动作，「获焦无副作用」管的是 VO 光标**路过**。只要「进会话」是一个**明确动作**（会话列表里按 Return，或快捷键 T09），VO 光标路过会话列表的某一项只是选中、不打开，就不会因路过而标已读。
- **会冲突的那种设计**：「会话列表选中即打开」（很多聊天应用的侧栏如此：↑/↓ 切会话、右边立刻换）。这时开着「键盘焦点跟随 VO 光标」的用户，VO 走过列表就等于逐个进会话、逐个标已读。
- **另一层张力**（不是冲突，是取舍）：业界最好的先例（tdesktop 2026，未合并）改成「**被读到才算已读**」，与 F1「进会话即全标」方向相反；F1 是人定，这里只列出，不建议推翻。
- **F1 与 F2（落点 = 第一条未读）的顺序**：进会话那一刻先记下「第一条未读」再标已读，否则分隔线和落点都找不到。这是实现约束，不用人定。
- 列进「要人定的事」第 1 条（`state/handoff/ga11y.md`）。**人已定（013 B19-2）**：维持 F1，进会话直接标到最新；会话列表按默认「回车才打开」。
