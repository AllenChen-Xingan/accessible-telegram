## 一、MVP 怎么划

**MVP = 能日常替代官方客户端「读消息、回消息」的最小集。** 判一项进不进，只问一句：**少了它，你还会不会每天打开官方客户端？** 会，就进。
**MVP 的验收**＝你开着 VoiceOver，把 T01–T10（加上你收下的 T11+ 提议）逐项走通（roadmap 第六节；要不要再加「用一周」见 roadmap S3）。

### MVP

| 组 | 功能 | 为什么少不了 |
|---|---|---|
| 登录 | 手机号 + 验证码 · 二步验证密码 · 邮箱支（服务器要就得接）· 登出 · 当前账号 | 进不去什么都免谈（T01） |
| 会话列表 | 加载并按序维护（`loadChats` + 更新，不用 `getChats` 排序）· 每项：名字、类型、未读数、@提及数、静音、置顶、最后一条摘要 · 收藏夹作普通会话 | 主页面（T02） |
| 未读 | 未读数 · 总未读 · 跳到下一个有未读的会话（本地算）· 已读回执（**怎么把关见 F1**） | T02、T09 |
| 读消息 | 打开 / 关闭会话（成对）· 拉历史并循环拉够 · **进会话落点 + 未读分隔（F2）** · 逐条 `brief` · 按需 `detail`（回复谁、转发自、已编辑、表情回应计数、话题名）· 取被回复的那条 · **先选有效内容**（有「仅自己可见」的替代内容就读它）· **受限消息读「受限」和原因**，不读原内容 · 编辑 / 撤回 / 回应变化跟上（撤回原位留占位，001 拍板 7） | T03、T06；60 条未读时不能让人往上按 60 次 |
| 读全文 | **阅读视图**：一个键打开本条全文的只读文本区，VoiceOver 能按字 / 词 / 行读，Esc 回原处 · **复制本条全文** · **列出本条里的链接并交给浏览器打开**（`TextUrl` 的地址不在文字里，不做就手抄不了） | 长消息、验证码、地址、链接每天都有 |
| 附件 | 图、视频、语音、圆视频、文件、音频、GIF、贴纸、单 emoji 的描述（类型 + 说明文字 / 文件名 / 时长 / 大小 / emoji）· 下载（播报进度与完成）· 交给系统应用打开 | T07；打不开一份 PDF 就得回官方客户端 |
| 语音 | **播放语音消息**（**见 F3**）· 标记已听（对方看得到，按 L1 把关，见 F1） | 私聊语音很常见 |
| 系统消息 | 进群 / 退群 / 被移出 / 改名 / 改头像 / 置顶 / 建群 / 联系人注册有专门读法；其余落「泛化系统消息」读类型名 | 群里天天有 |
| 发 | 发文字 · 回复某条（话题群里沿用被回复那条的话题；话题群里新发消息先拒发并读出原因）· 发送结果（已发送 / 失败原因）· **重发失败** · 过发送闸与确认（001 拍板 9、10） | T04；断网发失败时读屏用户看不见红叹号 |
| 提示 | 新消息提示（001 拍板 3 的组合）· 后台系统通知（001 拍板 4）· **静音 / 取消静音一个会话** · 「是否静音」按**有效静音**算（会话设成「跟随默认」时继承私聊 / 群 / 频道的全局设置，全局设置的编辑在第二批） | T05；吵群会一直打断读屏；只看会话自身会误报 |
| 搜索 | 搜会话（本地 + 服务器）· 本会话搜消息 · 全局搜消息 · 选中结果跳回原消息上下文 | T08；几百个会话方向键走不完 |
| 状态 | 连接状态播报 · 「在线」状态（**怎么发见 A2**）· 代理（**进不进见 A5**） | T10 |

### 不做（对照 `.42cog/intent.md`「不做什么」）

| 不做 | 理由 |
|---|---|
| 通话（语音 / 视频 / 群通话） | 意向书第一阶段明确不做；TDLib 只给信令，媒体要另接一整套。**只读出「未接来电」这类通话记录消息** |
| Stories、亲密好友名单 | 意向书明确不做；视觉为主 |
| 群 / 频道管理后台（改权限、封禁、审批入群、设管理员） | 意向书明确不做 |
| 支付、星星、礼物、TON、付费消息 | 意向书明确不做支付。**相关系统消息照样落泛化节点读出类型，不崩** |
| 机器人开发、小程序、商业功能 | 意向书明确不做机器人开发；小程序是网页，无障碍不可控 |
| 删号 | 不可逆，且官方客户端可做 |
| 网络流量统计、相似频道推荐 | 不在日常聊天主路径 |

## 三、AI 按「确定的就执行」定下的（可推翻）

- **新消息提醒自己做，不用 TDLib 通知接口**：按 `updateNewMessage` + 静音设置 + 001 的 `notify` 策略做。`inventory.md` 注意 A-1 原把它列为待人定；AI 判它属于实现选择：TDLib 的 `updateNotification` 系列要另开选项、自带分组逻辑，和 001 已定的「`notify` 是纯逻辑、可注入时钟」重复。后台系统通知（001 拍板 4）照样从 `notify` 出
- **会话排序自维护**：`getChats` 的结果只作参考（它的注释原话 "For informational purposes only"），以 `updateChatPosition` 为准
- **相册不建专门的读取接口**：按 `media_album_id` 在渲染时合并（与 tree 对齐）
- **语音收到就下**：TDLib 不会按自动下载设置自己下（`inventory.md` 注意 C-4），MVP 写死
- **001 第一刀第 8 块（`atg-cli history`）从「可选」升为必做**：T03 的数据部分离不开它
- **标记已听**（`openMessageContent` `tl:14205`）对方看得到，归 L1，与已读同一道把关（已告 infra 补进契约）

## 四、⚠️ 待人拍板

> ✅ **已拍板（2026-10-25）**：结果见 `docs/plan/003_decisions-b2.md`。下面的题面保留作依据。

AI 不代填。每条都写了选项、代价和建议。roadmap 末尾另有 S0–S3（排期），infra 契约另有 A1–A5——**F1 = A1、A2 / A5 只在这里给指针，不问你两次**。

**几个词**：**块**＝一份 ≤3 天、能单独验收的活；**编译名额**＝全机同一时刻只许一处重编译，要排队；**L1**＝对别人可见但不发内容的动作（已读、正在输入、在线、已听）；**读屏**＝VoiceOver。

**F1（= 契约 A1）. 已读回执怎么把关**

你在本客户端读了，对方会看到「已读」；语音听了，对方会看到「已听」。`.42cog/real.md` 红线约束的是**开发、测试和 AI 代操作**——你本人在界面里读时，发不发已读是体验选择。难点在：**AI 用 computer use 在界面上读消息时，界面分不出是你还是 AI**（001 拍板 9 在「发送」上认过同一个漏洞）。

- A. 进会话就把已读标到最新一条（和官方客户端一样）
- B. **焦点经过哪条就标哪条**（`viewMessages` 本来就按条发，`tl:14199`）；CLI / AI 默认不标
- C. 一律不自动标，只在你按「标为已读」时标：最安全；但未读数一直不清，T09「下一个未读」会反复跳到你读过的会话
- 另需定：AI 经界面读时怎么办——(i) 接受（视为你在旁边）(ii) 界面里设一个「AI 代操作」开关，开着时一律不标
- 建议：B + (ii)

**F2. 进一个会话，焦点落在哪**

- A. 第一条未读（上面有「以下为未读」分隔）：60 条未读时从头往下读即可；官方客户端也是这样
- B. 最新一条：T03 原文写的是「从最新一条往上逐条读」
- 同一条里一并定：点系统通知进来、选中搜索结果进来，都落在那条消息上
- 建议：A。这会改 T03 的判据措辞，由你写

**F3. MVP 要不要能直接播放语音消息**

Telegram 语音是 OGG 封装的 Opus。macOS 自带框架**大概率**不能直接播 .ogg（**未实测**；也可能只缺 OGG 拆包、Opus 本身能解，M2.6 选型时先核）。

- A. 进 MVP：先在 CLI 做通（`atg-cli play`：播放 / 暂停 / 倍速 / 前后跳几秒，状态逐行输出），再接界面（键位避开 VoiceOver）；多约 2 块，可能要一次编译名额。声音从哪个模块出，见 F8
- B. MVP 只读描述 + 下载，你用别的播放器打开
- C. 放第二批
- 建议：A。少了它，你每天还得为语音回官方客户端

**F4. 语音转文字要不要依赖 Telegram 会员**

TDLib 的 `recognizeSpeech` 对非会员按每周试用次数给（`updateSpeechRecognitionTrial` `tl:11921` 带 `weekly_count`，按文档可以为 0），单条时长有上限。

- A. 只用 Telegram 的：零成本，非会员可能用不上
- B. Telegram 的优先，额度用完退到本机离线转写（macOS 自带语音识别能否离线转中文**未实测**）：语音不出本机，多一块工作
- C. 不做，只靠播放
- 建议：第二批做 B

**F5. 图片要不要「描述」**

Telegram 图片没有替代文字，现在只能读「图片 + 说明文字」。

- A. 只读「图片 + 说明文字」（MVP 就这样）
- B. 第二批加本机文字识别（macOS 自带，离线、不外发）：截图、海报里的字能读出来
- C. 再加视觉模型描述画面：要把图片发给外部服务，违背 `.42cog/real.md`「隐私」，除非你明确允许
- 建议：A → B，不做 C

**F6. 收到的「对方正在输入」「有人给你回应」要不要播**

两者都来得很频繁。

- A. 默认都不播：只存状态，在会话详情里能查到
- B. 只在当前打开的私聊里，停手后播一次「对方正在输入」
- 建议：A，试用后再看要不要 B

**F7. T11+ 提议收哪几条**

见第二节表格。

**F8. 播放声音的代码放在哪个模块**（F3 选 A 才需要定）

架构方案 `docs/plan/001_arch-stack.md` 第 51 行定了：`atg-core`「不管任何界面、任何 macOS 调用、任何发声动作」。可语音播放要先在命令行做通（`.42cog/intent.md`「命令行优先」），命令行和界面都得能出声。

- A. 新建一个小模块 `atg-audio`（不依赖界面框架），命令行和界面共用：不破 001 的边界；多一个模块要维护
- B. 放进 `atg-core`，并改 001 第 51 行：最省事；`atg-core` 从此会碰 macOS 音频
- C. 命令行和界面各写一份：违反「同样的东西只留一份」，不建议
- 建议：A（infra 也这样建议）

**指针（在 infra 契约里问，这里不重复）**

- **A2 在线状态与发「正在输入」**：`specs/contracts/actions.md`「待人拍板」A2。本稿 MVP 只写「在线状态按 A2」，没替你定
