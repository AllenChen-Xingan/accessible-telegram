# 两类发现 · GPUI+AccessKit 能否撑起读屏友好的聊天界面，Telegram 层用 grammers 还是 TDLib

> 2026-10-23。读完两类来源，落成两类发现：**它们做到的** 与 **它们没做的**。
> **分析的成果不是综述，是这两张表。**
> 综述回答「别人做到哪了」，这里回答「**我该先做哪一件**」。

## 一、它们做到的

逐项核对

四态判定，不许用「基本满足」这种含糊说法。

| # | 不可妥协的那条 | 状态 | 差距是什么 | 修起来要什么 | 分级 |
|---|---|---|---|---|---|
| 1 | 列表可逐项读、焦点可程序控制 | **部分**（缺屏幕外的项） | 角色 / 名称 / 选中 / 第几项共几项、程序移焦点都原生（`findings-gpui.md` 第 1、2 条）；但虚拟化列表只把可见项放进树，VoiceOver 自由浏览走到边缘会断 | **接一根线**：容器持焦点 + `aria_active_descendant` + 本项目接方向键「先滚再选」+ `size_of_set` 报总数 | P1 |
| 2 | 能播报、不抢焦点 | **部分**（缺专用接口，且未实测） | GPUI 无 `aria_live`；但公开出口能拿到 AccessKit 节点，设 `Live` 后 accesskit_macos 会发公告通知（`findings-gpui.md` 第 4 条）。是否打断当前朗读、重复内容不播，都还不知道 | **接一根线**（播报元素薄壳）+ **一次实验** | P0（未实测就是未知） |
| 3 | 用户账号 + 实时更新 + 快 | TDLib **已实现**；grammers **部分** | TDLib 登录、补齐、已读、正在输入、本地缓存全现成；grammers 缺消息缓存、已读和正在输入只有 Raw、登录有崩溃分支（`findings-tg.md` 表格） | TDLib：接一根线（`tdlib-rs` + `download-tdlib`）；grammers：缓存要**从头造** | TDLib 路线 P2 / grammers 路线 P1 |

**「修起来要什么」这一栏最要紧。** 同样是「缺」，成本差一个数量级：

| 缺法 | 成本 |
|---|---|
| **能力已经有了，只是没接上** | 低成本高收益，优先做 |
| **能力本身就没有** | 要立项，另算 |

判「缺」的时候多走一步，去底层看看是哪一种。

## 候选之间

若这次是选型，横向拼一张表——**同一批核查项，逐格对照**。

Telegram 层（同一张核查表，详见 `findings-tg.md`）：

> ⚠️ TDLib 一列读的是 1.8.69 源码，但 tdlib-rs 实际下载的是 **1.8.61**（`tdlib-rs/build.rs:21,199-205`）。登录、更新、`only_local` 这些老能力大概率一致，但原型落地前要按 1.8.61 复核一遍。

| 核查项 | grammers 0.11（Codeberg 正本） | TDLib（源码 1.8.69 · 交付 1.8.61）+ tdlib-rs 1.4.0 |
|---|---|---|
| 用户登录 + 二步验证 | 原生，但 `PaymentRequired` 分支 `unimplemented!()` | 原生，完整状态机 |
| 实时更新 + 断线补齐 | 部分：已读 / 正在输入只有 Raw；状态需手动保存 | 原生，全是一等更新，自动补齐 |
| 本地缓存 / 冷启动 | 没有（只存会话元数据） | 原生，`only_local` 可先出缓存 |
| 构建 | 纯 Rust，几分钟 | C++ 重；有预编译（39.7 MB），但由绑定作者个人发布 |
| 测试服务器 | 部分：要手改 DC | 原生：`use_test_dc` |
| 维护 | 活跃、单人、未到 1.0 | TDLib 活跃；**tdlib-rs 落后 8 个小版本、单人** |

## 二、它们没做的

| 找过什么 | 结论 | 是哪一种 |
|---|---|---|
| GPUI 的 live region / 播报接口 | 无专用接口，有底层出口 | **没顾上做**（AccessKit 接入 2026-05 才合并，后续 PR 一直在补）——机会：本项目薄壳验证后可回馈上游 |
| GPUI 屏幕外列表项进树 | 无 | **没顾上做**，但属于虚拟化的固有取舍；用 active_descendant 绕开，不硬造 |
| GPUI 测试平台里拿无障碍树 | 无（测试平台不实现 `a11y_init`） | **没顾上做**——验收先走真窗口 + macOS AX 接口；以后可给上游提 PR |
| VoiceOver 下聊天界面「新消息不打断朗读」的现成做法 | 两个候选都没给答案 | 正是真难题 1，**多年没解决** → 必须自己跑 |
| TDLib（tdjson）↔ GPUI 的衔接与延迟 | 无现成数据 | 输入清楚、结果未知 → 自己跑 |

### 要跑的实验

| 编号 | 假设 | 改变哪个取舍 |
|---|---|---|
| `exp001-announce` | 设 `Live::Polite` 的节点值变化时，VoiceOver 会播报、不移动焦点、不打断正在朗读的内容 | 若不成立：播报改走 NSAccessibility 直发通知，或重新评估 GPUI |
| `exp002-tdjson-latency` | ① 冷启动到会话列表可读 ② 新消息到达 → TDLib 回调 → GPUI 重绘 → 无障碍通知发出，**分段计时**，都在可感知阈值以下 | 只有慢在 TDLib 那一段（用 grammers 跑同一段做对照）才改选 grammers；慢在界面层则改界面 |
| `exp003-list-nav` | 方向键驱动的列表（active_descendant + 先滚再选）在 VoiceOver 下能跨屏连续逐项读，读出「第几项共几项」，焦点不丢 | 若不成立：拍板 3 改 B，或重新评估 GPUI |

三个实验都需要 Rust 和一个编译名额。缓存存在不等于冷启动快，所以 `exp002` 单独量冷启动。

⚠️ **空白是结论，不是失败。**

⚠️ **同样是「没有」，意义相反**：

| | 意味着 | 怎么认出来 |
|---|---|---|
| **没顾上做** | 可能是机会——他们没空，你有 | 从来没人提过、也没人试过 |
| **做不到** | 可能是天堑——多少人试过都撞回来了 | 提交历史里试过又回滚、issue 里讨论过又关掉 |

**空白不都是机会，有些空白是别人替你踩过的坑。**

### 该不该自己跑一个

| 判据 | 结论 |
|---|---|
| 搜一下就有答案 | **不用跑**，去查 |
| 别人做过，只是我没找到 | **先去找** |
| **这道难题多年没解决** | **跑它**——不可能今天拍脑袋解决 |
| 输出清楚，却不知道拿什么喂它 | **跑它**——输入不清楚，正是实验的场合 |

要跑就去 `docs/experiments/` 开一个 `expNNN-<slug>/`：**假设 → 做法 → 结论 → 改变了哪一个取舍**。
**没改变取舍的实验，不值得跑第二个。**
