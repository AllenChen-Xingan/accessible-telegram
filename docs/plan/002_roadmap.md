## 〇、一句话

**先做 tdlib-rs 补丁（M0.0），补丁做完才开第一刀（S0）；再打地基（M0 其余），让命令行能读（M1）、能回（M2），再把同样的能力接进界面（M3 读、M4 回）。中途有一个「日常环」检查点：界面能读、能回文字、有新消息提示音时，你就可以开始试用。M4 走完 = MVP，之后加一步「一周只用它」（S3）。之后是第二批（M5）、再往后（M6）。**

每项能力都**先 CLI 后 GUI**（`.42cog/cog.md`「命令行优先」）：同一项能力，`atg-cli` 那块没过验收，`atg-gui` 那块不开工。

## 二、建议推进顺序（含「日常环」）

同一时间只推一个 `status:active` issue（`specs/workflow.md` 第 2 节）。

1. **M0.0 tdlib-rs 补丁**（S0 人定：补丁做完前第一刀一块都不开）。tree 已建的 `src/atg-core` 原型保留不删、暂停开发。下一件事 = tdlib-rs 补丁。（M0.3 契约是文档、不在第一刀 8 块里，AI 判它可与补丁并行；人若不同意就排到补丁后面）
2. 补丁过验收后：M0.1 → M0.2（在原型上续做）
3. M1 全部（含 M1.8 本机接口）
4. M2.1 发送闸 → M2.2 send → M2.3 watch
5. M3.1 → M3.2 → M3.3 → M3.4 → M3.5 → M3.6。**S2 人定：盘够就并行**——M1 之后开两个 worktree，一条走第 4 步（M2.1–M2.3，接着第 8 步里的 M2.4–M2.7），一条走第 5 步（M3.1–M3.6）；开之前先看盘（GPUI 的 `target/` 几十 GB），不够就串行
6. M4.1 输入框 → M4.2 确认 → M4.3 新消息提示
7. ★ **日常环检查点**：会话列表、消息列表、详情、读全文、发文字与回复、新消息提示都通了。你开始在**测试服务器**上试用（F1 已定：进会话就标已读，和官方客户端一样）。这时暴露的问题（落点、读法、焦点）进下一轮头号任务
8. M2.4 search → M2.5 下载 → M2.6 CLI 语音播放 → M2.7 CLI 删除 → M3.7 附件打开 → M3.8 语音播放 → M4.4 后台通知 → M4.5 搜索界面 → M4.6 删除 → **MVP 验收**
9. **一周只用它**（S3 人定）：MVP 验收之后，你连续一周只用本客户端读和回。**这一周 AI 不碰真实账号**（不经 CLI 读、不经界面操作）
