# 无障碍 Telegram（macOS · VoiceOver 优先） · 意向书

> 意向即行动。这一份文件决定这个系统会长成什么样。
> **只有一处必须你亲自过目：收敛方向。其余是草稿，看不顺眼再动。**
> **它现在一定是粗的。跑完 `-research` 会回来改——四步是循环，不是直线。**

## 收敛方向（唯一）

**做一个速度很快、AI 友好、无障碍友好的 Telegram 版本。**

三个词，各有一把尺子。每件产出至少要让其中一把变好，且不能让另两把变差：

| | 是什么意思 | 怎么量 |
|---|---|---|
| **速度很快** | 冷启动快、切会话快、按键到读屏开口没有停顿 | 冷启动时间；切换会话到第一条消息可读的时间；按键到无障碍通知发出的延迟（目标：都在可感知阈值以下，具体数字由 `atg-research` 定） |
| **AI 友好**（agent 友好） | ① **命令行优先**：每项功能先在 `atg-cli` 里做通（结构化输出），再接到界面上；② **无障碍树就是 agent 的接口**：界面上每个元素都有清楚的角色、名称、状态和稳定标识，用 computer use 的 AI 不靠截图、直接读树就能操作。发消息等对外动作，无论走哪条路都须人确认（**例外**：人以「直发模式」启动参数运行时，本次运行免确认，见 `docs/plan/001_arch-stack.md` 第七节第 11 条） | `specs/tasks.md` 每项任务：AI 能否只用命令行完成；AI 能否只读无障碍树（不看像素）在界面上完成 |
| **无障碍友好** | 只靠键盘 + VoiceOver 就能顺畅完成日常全部操作 | `specs/tasks.md` 每项任务的 ① 能否完成 ② 按键次数 ③ 读屏有没有读错、漏读、乱跳焦点 |

推进不了这三把尺子的产出，再漂亮也不算数。

## 真难题

1. **流动的聊天界面在读屏下不丢「定位感」。** 新消息不停涌进来、往上翻又加载更早的历史、对方正在输入、消息被编辑或撤回——这些时候焦点不能跳走、不能丢、不能打断正在朗读的内容，同时用户又得知道「有新东西来了」。官方客户端和各家第三方客户端多年都没做好，这正是本项目存在的理由。
2. **把富内容压成一句好听的话。** 一条消息可能同时带着：发送人、回复引用、转发来源、图片 / 贴纸 / 语音 / 文件、表情回应、内联按钮、已编辑标记、时间、已读状态。既不能啰嗦（每条读十秒没人受得了），也不能丢信息（漏了「这是回复谁的」就看不懂上下文）。读法需要分层：先读最要紧的，细节按需展开。

> 不算真难题的（手工能绕或单点能解）：接 Telegram 协议（grammers / TDLib 现成）、画界面（GPUI 现成）、把元素暴露给 VoiceOver（GPUI 已内置 AccessKit，`.role()` / `.aria_*()` 标注即可）。

## 不做什么

| 不做 | 为什么不做 |
|---|---|
| 视觉上复刻官方 Telegram 的精致动效 | 方向是读屏 + 键盘好用；视觉清楚、对比度够、支持放大即可 |
| 第一阶段不做 iOS / Windows / Linux | 先把一台 Mac 上的 VoiceOver 做透；GPUI 跨平台，以后再说 |
| 第一阶段不做通话、Stories、频道/群管理后台、支付、机器人开发 | 不在日常聊天主路径上，做了只会稀释 |
| 不自己实现 MTProto 协议与加密 | 安全敏感且已有成熟实现，自己写只会出事 |
| 不长期 fork、魔改 GPUI | 无障碍能力缺什么，先在本项目里绕；确实是上游的缺口就给 Zed 提 PR，不维护私有分支 |
| 不靠「自己用语音合成念出来」代替系统无障碍接口 | 那样只服务读屏，盲文显示器、语音控制、切换控制都用不了；一律走 AccessKit → macOS 无障碍接口 |

## 真相源与权重

冲突时信谁，从高到低（`atg-research` 来补全）：

1. **我本人用 VoiceOver 的实际体验**——读得顺不顺、找不找得到，最终只有人能判
2. **macOS VoiceOver / NSAccessibility 的实际行为**，以及 AccessKit 文档
3. **Telegram 官方 API 文档**（core.telegram.org）与所选库（grammers / TDLib）的文档
4. **GPUI 源码**（zed-industries/zed 主干，`crates/gpui`）——无障碍接口还年轻，以代码为准，不以博客为准
5. 其他客户端的做法（官方 macOS 版、Telegram Desktop、Unigram 等）——只作参考

## 作品区

- 目录：`src/`，按 Rust 模块（crate）分，清单以根目录 `Cargo.toml` 的 workspace 为准
- 系统实际产出什么：一个能双击打开的 macOS App，登录自己的 Telegram 账号后能聊天
- **怎么算合格（验证闭环）**：
  - 规则验证（机器）：`cargo fmt --check` · `cargo clippy` · `cargo test`；「消息怎么读」的读法函数有快照测试；界面的无障碍树能导出并对照检查（每个可操作元素都有角色和名称）
  - 判据验证（AI）：对照 `specs/` 里的读法规约与正反例审查
  - 实效验证（人）：我本人开着 VoiceOver，按 `specs/tasks.md` 逐项走一遍；走不通的那一项就是下一轮的头号任务
